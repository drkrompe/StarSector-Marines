Closes the "Installable public build" gate in `v0.1-alpha.md`. The target is

## Scope

1. One version everywhere: `0.1.0-alpha` in `mod_info.json`, `build.gradle`
   and the asset pipeline. The manifest has a real description.
2. One command that produces the download: `gradlew.bat packageRelease`.
3. No debug or test surface reachable in a player's install.
4. Player-facing install instructions and a changelog with known issues,
   shipped inside the zip.
5. A list of shipped assets that may not be redistributable, with an owner
   decision for each.
6. An ordered release-day checklist.

Not in scope: replacing assets, a version-checker integration, or any live
acceptance of the gameplay gates. Those gates are tracked in `v0.1-alpha.md`.

## Package

`gradlew.bat packageRelease` writes
`build/release/StarsectorMarines-<version>.zip`. Its one top-level folder,
`StarsectorMarines/`, is the install folder, the same name `deployMod` uses.
It holds:

- everything under `mod/` except the two generated folders and `.gitkeep`
  files;
- `jars/StarsectorMarines.jar`, the shaded jar only, after
  `verifyModJarBoundary` has passed;
- `sounds/`, transcoded into a fresh `build/release/sounds` by
  `:asset-pipeline:processReleaseAudio`. That folder holds exactly the clips
  `audio.json` lists. `mod/sounds` is never pruned, so packaging from it
  could ship a stale clip from a developer checkout.

The task fails when `mod_info.json`'s version differs from `build.gradle`'s, or
when any entry would land outside the top-level folder.

Measured on 2026-10-31 (`main` after the CHEAT and Onslaught cheats):

- 390.7 MB, 3320 files (417.8 MB uncompressed).
- graphics 186 MB, cinematic 112 MB, sounds 96 MB (1431 clips), jar 20 MB,
  data 3.5 MB.
- No `art-source/`, `build/`, raw-sheet, prompt or script file is inside.

The first measurement, on 2026-10-21, was 270.4 MB and 2186 files; the growth
is new art, the cinematic and the ElevenLabs voice and effect clips.

## Debug surfaces and cheats

Two gates. `DevConfig.DEV_MODE` is read from the JVM property `marines.dev`.
It is **off** unless the game is launched with `-Dmarines.dev=true`.
`runStarsector` passes the property, so developer runs are unchanged.
`runStarsector -PplayerBuild` launches the game as a player sees it, and a
player's install never carries the property. Every per-surface `DevConfig`
flag is ANDed with it, so a release needs no edits.

`Cheats` is the alpha's player cheat switch: the **CHEAT** key on the mission
board, off by default in every build (a dev build too) and saved with the
game. It opens the sandbox missions and their force
composition, offers the Onslaught power in every briefing, and gives a battle
one action, Win. Runtime diagnostics never
follow it; they need `DEV_MODE`.

| Surface | How it is reached | Gate |
|---|---|---|
| Debug missions client on every planet | Mission select | `Cheats` |
| HQ debug button | Company HQ | `Cheats` |
| Debug mission catalog (every mission type and tier; `MissionSource.DEBUG*`) | The two entries above | `Cheats` |
| Briefing debug drawer: fixture personnel, mech, air and warship pickers | Debug-source missions | `source.isDebug()` + (`Cheats` or `DEBUG_*_PICKER`) |
| Store "[Cheat] Free Licenses" | Store | `Cheats` |
| Onslaught power (`SpawnInOnslaught`) in every briefing's command deck | Briefing | `Cheats` (debug missions always) |
| Battle switch, labelled CHEAT in a player build (DEBUG in dev). In a player build, turning it on opens Win (skip mission) and Add Onslaught directly beside it; Add Onslaught puts Spawn in Onslaught on the power bar mid-battle and then disappears. A dev build's switch opens the same two beside it, as well as its diagnostic panel | Every battle | `Cheats` or `DEV_MODE` |
| Battle diagnostic rows behind that switch: render and relief dials, influence and commander pictures, force reinforcement, commander trace capture and dumps, spawn mech family, turret author, docking paths, auto spike dumps | Every battle, in dev | `DEV_MODE` only |
| Squad-plan readout, tick-profile panel, warship debug panel with F5–F12 | Every battle, in dev | `DEV_MODE` (`PROFILE_TICK_PHASES`, `DEBUG_WARSHIP_PICKER`) |
| Z: zone-graph overlay. F5: vehicle state dump | Any battle, ungated before | `DEV_MODE` at the call site |
| Shift+right-click: destroy the wall under the cursor | Any battle, ungated before | `DEV_MODE` at the call site |
| Docking-path debug drawing (defaulted on) | Convoys | Default is `DEV_MODE` |
| "Marines Debug" campaign intel: skip days, spawn offers and raids, force-complete contracts, reseed houses, learn suits | Intel tab | `CAMPAIGN_DEBUG_INTEL`. A player build also **removes** an entry an older save carries |
| S0 combat probe: Ctrl+Shift+B / Ctrl+Shift+K on the campaign map, F10 in that combat | Campaign map | `S0_COMBAT_PROBE` |
| Free command powers, drop-count override, house-gating bypass | Off already | Also ANDed with `DEV_MODE` |
| UI workbench | Registered, but nothing navigates to it | `DEBUG_UI_WORKBENCH` |

There are no Console Commands integration, no debug `rules.csv` rows and no
`isDevMode()` checks. `-Dbattle.*` and `marines.debug.screenTrigger` are
tuning properties a player would have to put in vmparams; their defaults are
production values.

`UiWorkbenchScreen` is still registered, but nothing a player can click
reaches it. `DebugMissionScreen` is reached only with CHEAT on.

## Player docs

`mod/README.txt` covers install, update, memory and removal.
`mod/CHANGELOG.txt` holds the changelog and known issues. Both ship at the
zip's top level beside `mod_info.json` and `CREDITS`. The mod has no required
dependencies: no LazyLib, MagicLib or GraphicsLib. Nexerelin is optional
(`campaign/nexerelin`, `data/config/exerelin/customStarts.json`).

## Release-day checklist (owner)

1. From a clean, current `main`, run `gradlew.bat build`, then
   `gradlew.bat packageRelease`. Note the zip size the task prints.
2. Fresh-install smoke test:
   - unzip into an empty `mods/` of a clean install;
   - enable only Starsector Marines;
   - start a new campaign and confirm the mission board's CHEAT key is off,
     and with it off there is no Debug missions client, no HQ debug button,
     no battle CHEAT switch and no "Marines Debug" intel;
   - play the opening operation;
   - turn CHEAT on: the Debug missions client and HQ button appear, a debug
     mission's briefing offers force composition, and the battle's CHEAT
     switch opens only a Win button beside it, with no top-centre panel,
     squad-plan readout or tick profile.
   Repeat with Nexerelin enabled.
3. Optional: run `runStarsector -PplayerBuild` from the repository to check
   the same surfaces as a player sees them.
4. Tag the commit: `git tag v0.1.0-alpha`, then `git push origin v0.1.0-alpha`.
5. Upload the zip to the file host: a GitHub release on the tag, with the zip
   attached and the changelog pasted in, or Google Drive / Mega as a mirror.
   Use a direct link that does not expire.
6. Forum post in the Fractal Softworks Mods board:
   - title `[0.98a] Starsector Marines 0.1.0-alpha`;
   - the description, screenshots, requirements (0.98a-RC8, Nexerelin
     optional, new campaign), install steps from `README.txt`, known issues
     from `CHANGELOG.txt`, the download link and credits.
7. Version Checker: not integrated in this build. To support it later, add a
   `.version` file and `data/config/version/version_files.csv`, and host the
   master `.version` file at a raw URL. That can follow in 0.1.1.
8. Optional: post the forum link to the Starsector Discord's mod-updates
    channel.
9. Watch the thread and collect `starsector.log` from bug reports for the
    first hotfix.
