# Tender machinery

Original deterministic DSP masters, authored locally with Python's standard library.
No licensed recording, remote generation or voice is used. `generate.py` retains the
reproducible design: mono 44.1 kHz 16-bit PCM, peak bounded to 0.72, short edge fades.
Run `python generate.py` to regenerate the WAVs, then the ordinary
`gradlew.bat :asset-pipeline:processAudio` to encode their positional OGG outputs.

Launch rises from a bay-release click into a small electric motor; docking falls
into a metal latch. Welding combines an uneven arc hiss, low electrical hum and
fast crackle, with three noise variants. Damage is a brief electrical splutter.
Stand-down falls through two alert tones; completion seats the mechanism and gives
two restrained confirmation tones. These are sound-designed effects, with live mix
and taste acceptance still requiring an in-game listen.

Audition the retained WAV files directly, or use the Shepherd debug tender and lay
a build near the camera. Listen for staggered departures, arc bursts only while
the torches work, completion, then recovery clicks. Let builders take fire to hear
the splutter and stand-down. At accelerated time the presentation admits at most
one weld per 300 ms across the battle, independently of the simulation's site clocks;
flight, damage, alert and completion have separate budgets. No held loop exists:
pause, cancelled work and lost hulls leave only the current sub-second clip tail.
Ordinary positional playback preserves distance, panning and the host SFX settings;
hostile cues use the same revealed-cell gate as tender effects.
